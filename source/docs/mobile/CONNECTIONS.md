# Подключения и выпуск на Android

Д56: доступы импортирует автор на своём устройстве. APK не содержит
рабочих токенов, ключей или адреса SSH. GitHub, SSH и метка независимы:
заполнять только нужные разделы. ИИ в приложении нет.

## Импорт

«Настройки → Импортировать подключения» открывает системный выбор JSON,
затем PIN/биометрию телефона. Профиль `smi-access/v1`:

```json
{
  "schema": "smi-access/v1",
  "github": {"repository": "dpsmpx/SocialMediaImage", "token": ""},
  "ssh": {
    "host": "", "port": 22, "user": "",
    "root": "/home/account/site/public_html",
    "private_key": "", "passphrase": "", "known_hosts": ""
  },
  "mark_key": "",
  "credentials": {"CS_PROD_TELEGRAM_BOT_TOKEN": ""},
  "destinations": {
    "tg-devlog": {"status": "active", "account": {"id": ""}, "target": {"id": ""}}
  }
}
```

`private_key` — полный текст существующего ключа Termux, `known_hosts` —
его записи доверенных серверов, `mark_key` — 64 hex-знака существующего
ключа метки. Имена/пути примерные. Неизвестный или сменённый SSH-ключ
отклоняется; приложение не принимает его автоматически. Ed25519
поддерживается через лёгкие криптографические классы Bouncy Castle,
системный криптопровайдер Android не заменяется. Если путь public_html
содержит ссылку, нужен его настоящий полный путь.

Числовые id канала и бота Telegram задаются здесь, без переноса в Git.
Перед отправкой Bot API сверяет аккаунт и канал; названия канала
недостаточно. Прочие адресаты определяются конфигурацией проекта.
Токен GitHub должен иметь доступ к выбранному репозиторию: чтение для
получения/источников, запись contents и pull requests для черновиков.

Импортированный профиль шифруется Android Keystore, исключён из
резервного копирования и SAF. Открытая копия живёт только в работающей
службе. Остановка/перезапуск требует нового входа. Исходный JSON
импорта остаётся у автора: после успешного импорта его можно убрать
из общей памяти; старые файлы/ключи Termux приложение не удаляет.
«Удалить сохранённые доступы» удаляет шифротекст приложения.

## GitHub и факты

Сравнение показывает локальные, удалённые и конфликтующие изменения.
Получение сохраняет прежнюю рабочую папку целиком; конфликтующая
удалённая версия попадает в `data/sync-conflicts/<id>/`. Разберите обе
копии внешним редактором и удалите разобранные файлы конфликтов.
Неизменённые локальные материалы не затираются при отправке: она
создаёт `mobile/draft-*` и draft PR, основную ветку не меняет. Просмотр
и слияние — по кнопке открытия PR на GitHub. Затем получите main:
это даст проверяемое подтверждение сохранения канона в Git.

«Факты → Обновить источники GitHub» сохраняет текущие SHA, дату,
доступность и состояние репозиториев из scope. Это наблюдения, не
утверждённые FACT и не замеры строк кода. Закрытый код не скачивается.
Недоступное явно имеет UNKNOWN / AUTH REQUIRED. Полный анализ истории,
веток, patch-id и reported-метрик — существующий конвейер в Termux:
«Полная история через Termux», распаковать пакет в домашнюю папку,
`python collect-termux.py`, выбрать полные локальные клоны и период,
импортировать `updated-sources.zip`, выполнить проверку. Старый набор
прогресса не перезаписывается; отсутствующая история не придумывается.

## Сайт

1. Собрать предпросмотр; открыть все страницы в браузере. Все ресурсы
   локальны. Служба поддерживает просмотр при уходе из приложения.
2. Проверить материалы, подготовить и явно одобрить нужные варианты.
   Сохранить канон в GitHub. Собрать production-выпуск.
3. «Подготовить метку в Termux»: экспортировать полный ZIP, распаковать
   в домашнюю папку Termux и выполнить `python run-termux.py`.
   Выполняйте сценарий из заново экспортированного приложением пакета:
   runtime берётся из APK, код возвращённого ИИ архива не исполняется.
   Инструкция зависимостей лежит в TERMUX.txt. Используется прежний
   алгоритм mark_build и ключ автора, сеть/выгрузка здесь не запускаются.
4. Импортировать `marked-*.zip`. Приложение сверяет HMAC-подтверждение,
   исходную сборку, все файлы и фильтр чувствительных данных. Чужой
   ключ, другая версия и неполный пакет отклоняются.
5. Открыть помеченную версию в браузере. «Сравнить и выложить» покажет
   сервер, точный отпечаток и добавляемые/изменяемые/убираемые файлы.
   Подтвердить конкретный выпуск после восстановления хостинга.
6. Новые файлы сначала загружаются вне public_html и сверяются. Старые
   сохраняются до полного результата, `.well-known` не меняется.
   Отказ записи возвращает прежнее; при потере связи/остановке остаётся
   журнал. Кнопка восстановления после нового входа откатывает
   незавершённое или завершает очистку уже подтверждённого выпуска.
   Если кто-то ещё изменил те же файлы, обе копии сохраняются и нужен
   ручной разбор. Новый выпуск до разбора не начинается.
7. Успех — только полное совпадение файлов хостинга и выпуска. Тогда
   сохраняются дата, уведомление и публичный манифест происхождения.
   Метки времени RFC3161/OTS — существующий последующий шаг CLI; их
   отсутствие видно в проверках реестра. Корень public_html не удаляется.

SFTP — исполнение разрешённой Д56 выкладки на устройстве автора,
альтернатива CLI rsync. Панели Beget нет. Смена файла на каталог требует
предварительной подготовки структуры; приложение сообщает об этом до
живых изменений. Профиль должен разрешать запись также в родительскую
папку public_html для временной/резервной копии.

«Скачать сайт с хостинга» дважды сверяет весь сайт по SFTP и сохраняет
его для работы без сети. Заглушка Beget не становится последним выпуском.
Дата прежней выкладки неизвестна, поэтому не выдумывается. Приложенные
локальные исходники могут не соответствовать скачанному старому сайту:
это явно отмечено. «Скачать всё» сохраняет сайт, исходники и сведения
выпуска, а не отдельную HTML-страницу.

## Соцсети и файлы

В «Материалах» доступны просмотр итогового текста/медиа, проверки,
подготовка и одобрение точного хэша. «Проверить и подготовить» также
проверяет и фиксирует новый импортированный канон, если он ещё не
запечатан. Это не одобрение: оно остаётся отдельной кнопкой. Изменение
уже зафиксированного канона блокируется, правка делается новой версией. Telegram — существующий официальный
Bot API; прочие площадки (VK, YouTube, Discord, GitHub, TikTok) — прежний
ручной путь Д33: пакет, размещение официальным приложением, запись
HTTPS-ссылки. Экспорт не означает публикацию. Журнал отличает успех,
ошибку и неопределённый исход; последний требует явной сверки и не
допускает автоматического дублирования. Точного расписания и редактора
статей в этой версии нет.

«Настройки → Открыть файловый менеджер» выдаёт SAF-дерево SocialMediaImage.
В системном Проводнике и SAF-подключении Total Commander есть рабочий
проект, экспорт и сборки. Рабочие файлы можно менять, снимки выпусков
доступны только для чтения. Приватная папка службы и vault не выдаются.
Экспорт дополнительно проверяет содержимое детектором секретов CLI.
