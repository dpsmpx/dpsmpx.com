# Резервирование

Решение — Д30. Соцсети — **не** резервная копия (§65): там лежат
производные, без канона, происхождения и истории.

## Что копировать

Всё ценное — в Git: каноны, варианты, медиа (`assets/`, экспорт),
происхождение, журнал публикаций, факты, решения. Вне Git у автора:
мастер-файлы видео, сырые выгрузки метрик, учётные данные.

## Три копии

| Копия | Как | Как часто |
|---|---|---|
| **GitHub** (`dpsmpx/SocialMediaImage`, закрытый) | push после каждого куска работы (`CLAUDE.md`) | постоянно |
| **Локальная** | `git clone`/`git pull` на машине автора + `python3 -m tools.cs bundle` → каталог сборки build/export | после публикаций, не реже раза в неделю |
| **Внешняя** | архив `bundle` (один `.tar.gz` с манифест MANIFEST.json) — на внешний диск или в облачное хранилище автора, **не** в соцсети | раз в месяц и перед крупными изменениями |

Мастер-видео и сырые метрики — в ту же внешнюю копию, отдельной папкой.

## Проверка копии

`bundle` после записи сверяет архив с манифестом (sha256 каждого
файла). Раз в квартал — восстановление в пустой каталог:

```sh
mkdir /tmp/restore && tar -xzf dpsmpx-content-*.tar.gz -C /tmp/restore
cd /tmp/restore && git init -q && git add -A && python3 -m tools.cs check schemas facts canonical publications
```

Архив самодостаточен: в нём данные, документы и код инструментов
(`tools/`, `tests/`, `website/`); нужны Python и PyYAML/jsonschema, для метки
изображений (Д41) — ещё numpy и Pillow (`tools/requirements.txt`).
