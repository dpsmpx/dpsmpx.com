# Профессиональный образ разработчика при закрытых проектах

**Вопрос.** По чему профессиональная аудитория (работодатели,
соавторы, коллеги) оценивает разработчика — и что делать, если главные
проекты автора закрыты (Galdhold, DPlang — Д17)?

## Источник

Marlow J., Dabbish L. *Activity traces and signals in software developer
recruitment and hiring.* CSCW 2013. Авторы рассмотрели следы
активности на страницах профилей GitHub через теорию сигналов и
опросили менеджеров и разработчиков, которые используют GitHub при
найме и поиске работы. Опрошенные считали сведения из аккаунтов GitHub
**более надёжными и проверяемыми**, чем статичный список навыков
(резюме). Пересказ основного вывода сверен по вторичному источнику
(arXiv 2303.14702, обзор раздела о GitHub-профилях), 04.10.2026.

## Вывод для автора

- Профессиональную аудиторию убеждают **проверяемые следы работы**, а не
  самоописания и эпитеты. Это совпадает с политикой утверждений (Д6,
  Д7): числа с датой и источником, без «лучший» и без оценок ИИ.
- У автора главные проекты закрыты — следов кода для посетителя нет.
  Замена — другие проверяемые сигналы:
  - настоящий результат: видео и снимки игры (Galdhold на телефоне);
  - масштаб с датой из реестра: строки C++, автоматические проверки,
    история коммитов и принятых слияний (GH-LOC, GH-CHECKS, GH-COMMITS);
  - метод словами: решения, правила, проверки, память проекта
    (AU-METHOD, AU-MEMORY) — без выдержек кода;
  - открытые малые проекты как широта (Andors-Love, PixRogue и др.).
- Ссылки — только на то, что посетитель может открыть: ссылка на
  закрытый репозиторий даёт 404 и работает против образа (IC-04).

## Как это использовано

`docs/platforms/GITHUB.md` (README профиля), презентационное
изображение CI-0001 (плашки-доказательства вместо эпитетов),
`CONTENT_STRATEGY.md`, §2 (профессиональная аудитория).
