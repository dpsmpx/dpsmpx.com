# API площадок: что можно автоматизировать

**Вопрос.** Что каждая площадка позволяет делать через официальный API
для аккаунтов автора — публиковать, править, удалять, грузить медиа,
откладывать, читать статистику, — какие нужны права и учётные данные,
какие лимиты и где автоматизация упирается в саму площадку
(`PLATFORM_VISION.md`, §2–3).

**Источники** — официальная документация, прочитана 4 октября 2026
(страницы скачаны из сессии; где страница не прочиталась — сказано).
Это исследование, а не решение: выводы — в `DECISIONS.md` (Д12, Д33) и
матрице `docs/platforms/PUBLISHING_CAPABILITY_MATRIX.md`
(машиночитаемо — `data/platforms/capabilities.yaml`).

**Главный вывод.** Автоматизация у площадок разная, и решает её не
наш код, а условия доступа площадки: Telegram (бот в канал) и Discord
(вебхук) дают публикацию без согласования; VK отдаёт права на стену
«в исключительных случаях» по запросу в поддержку; YouTube и TikTok
публикуют через API только приватно, пока приложение не прошло аудит.
Поэтому у системы обязательный **ручной путь** (пакет публикации для
автора) для каждой площадки, а адаптер — замена ручного пути там, где
площадка это позволяет.

---

## 1. Telegram — Bot API

Источник: core.telegram.org/bots/api (актуальная версия — **Bot API 10.3
от 24.08.2026**; 10.2 — 14.07.2026, 10.1 — 11.06.2026, 10.0 —
08.05.2026), core.telegram.org/bots/faq.

| Что | Как | Ограничения |
|---|---|---|
| Публикация в канал | бот — администратор канала с правом `can_post_messages`; `sendMessage`, `sendPhoto`, `sendMediaGroup` с `chat_id` = числовой id канала или `@username` | текст 1–4096 знаков после разбора разметки; подпись к медиа 0–1024; альбом — 2–10 элементов |
| Разметка | `parse_mode` HTML / MarkdownV2 или `entities` | ссылки открываются с подтверждением «Open this link?» |
| Медиа | загрузка `multipart/form-data` | фото ≤ 10 МБ, ширина + высота ≤ 10 000, соотношение ≤ 20; другие файлы ≤ 50 МБ (свой сервер Bot API — до 2000 МБ); по URL — фото ≤ 5 МБ, остальное ≤ 20 МБ |
| Правка | `editMessageText`, `editMessageCaption`, `editMessageMedia` | свои сообщения бота; чужие в канале — с `can_edit_messages`; 48 часов — только для business-сообщений |
| Удаление | `deleteMessage`, `deleteMessages` (1–100) | **только младше 48 часов**; бот с `can_post_messages` удаляет свои сообщения в канале, с `can_delete_messages` — любые |
| Отложенная публикация | **нет в Bot API** | откладывает наш планировщик (Д24); сервер сам может отложить тяжёлое сообщение — тогда `message_id = 0`, сообщение недоступно до отправки |
| Чтение | бот получает посты каналов, где он участник (обновления), пока работает; истории канала через Bot API нет | — |
| Комментарии | у канала — связанная группа обсуждения (`linked_chat_id`); пост автоматически пересылается туда (`is_automatic_forward`) | бот читает обсуждение, только если он в группе |
| Статистика | **нет в Bot API** (право `can_post_messages` открывает статистику в клиенте) | только ручная выгрузка (Д15) |
| Проверка личности | `getMe` (бот), `getChat` (id, title, username канала), `getChatMember` (права бота) | id канала может быть больше 32 бит — хранить строкой |
| Ошибки | `ok: false`, `description`, `error_code` («может меняться»), `parameters.retry_after` (флуд-контроль, секунды), `parameters.migrate_to_chat_id` | — |
| Лимиты | не больше ~1 сообщения в секунду в один чат; 20 в минуту в группу; рассылка ~30/с (платная — до 1000/с) | превышение — 429 с `retry_after` |
| Учётные данные | токен бота от @BotFather (бессрочный; отзыв и перевыпуск — `/revoke`) | токен в адресе запроса — не логировать адрес |
| Ссылка на пост | публичный канал — `https://t.me/<username>/<message_id>`; закрытый — `https://t.me/c/<id без -100>/<message_id>` | — |

**Личный профиль `@dpsmpx`** — Bot API от имени пользователя не
публикует. Пользовательский API (MTProto) — это вход в аккаунт автора:
исключено Д12. → только вручную.

**Вывод.** Канал-дневник — **полная автоматизация** публикации, правки
и удаления (≤ 48 ч) через бота. Нужны: бот, бот-админ канала с
`can_post_messages` (+ `can_edit_messages` для правки чужих),
**тестовый закрытый канал** для безопасного режима. Отложенная
публикация — своим планировщиком; статистика — вручную. Идемпотентного
ключа у Bot API нет: защита от двойной публикации — только наш журнал
(Д24); после обрыва связи без ответа повторять вслепую нельзя.

## 2. VK — VK API

Источники: dev.vk.com/ru/method/wall.post, wall.edit, wall.delete,
photos.getWallUploadServer, wall.getById, stats.getPostReach;
dev.vk.com/ru/api/api-requests; dev.vk.com/ru/api/access-token/getting-started,
…/community-token/in-community-settings. Страница версий
(`/reference/version`) — 404; «актуальная версия API — 5.131» по
странице запросов.

| Что | Как | Ограничения |
|---|---|---|
| Публикация на стену | `wall.post` (`owner_id`, для сообщества — `-id` и `from_group=1`) | **ключ пользователя из Standalone-приложения (Implicit Flow) с правом `wall` — «выдаётся в исключительных случаях через запрос в поддержку»** (адрес поддержки — на странице метода); ключ сообщества в методе не указан |
| Защита от дублей | параметр `guid` — «уникальный идентификатор для предотвращения повторной отправки», действует **1 час** | — |
| Отложенная публикация | `publish_date` (Unix time) | при публикации отложенной записи остальные параметры игнорируются |
| Контент | текст, фото, видео, сниппет ссылки или статья; ≤ 10 медиа; одна ссылка; с 04.06.2026 — нестандартные размеры в карусели кадрируются автоматически (`photo_attachments_crop`) | сниппет ссылки: соотношение 1:1…1:2,5, ширина ≥ 500 px |
| Правка, удаление | `wall.edit`, `wall.delete` | те же условия доступа, что у `wall.post` |
| Фото для записи | `photos.getWallUploadServer` → загрузка → `photos.saveWallPhoto` | право `photos` — тоже «в исключительных случаях» |
| Чтение | `wall.getById` | ключ пользователя или сервисный |
| Статистика | `stats.getPostReach` | ключ пользователя |
| Ключи | сервисный (бессрочный), пользователя (**1 час**), сообщества (бессрочный, только админ сообщества, отзывается в настройках) | — |
| Лимиты | по типу ключа и секции методов (сервисный — от 5 запросов/с в зависимости от числа пользователей приложения); превышение — ошибка `6 Too many requests per second`; количественные лимиты не раскрываются, при превышении — капча | — |
| Ошибки `wall.post` | 214 (запрещено), 219/224 (реклама), 220, 222 (ссылки запрещены), 225, 13000 (страйки сообщества) | — |

**Особенность автора.** Профиль `vk.com/dpsmpx` — личная страница,
закрыта для гостей (`docs/platforms/VK.md`); публичной стены сообщества
нет. Даже с доступом к API публикация на закрытой личной странице не
видна аудитории.

**Вывод.** VK — **ручное одобрение площадкой**: автоматическая
публикация возможна, только если VK выдаст приложению право `wall`
(запрос в поддержку) — до этого VK-вариант готовится системой и
публикуется автором вручную (пакет). Вопрос «личная страница или
сообщество» — к автору (`docs/platforms/VK.md`), он же решает, просить
ли у VK доступ.

## 3. YouTube — Data API v3, Analytics API

Источники: developers.google.com/youtube/v3/docs/videos/insert,
…/docs/videos, …/docs/thumbnails/set, …/determine_quota_cost,
…/revision_history (записи до 30.09.2026), developers.google.com/youtube/analytics,
developers.google.com/identity/protocols/oauth2.

| Что | Как | Ограничения |
|---|---|---|
| Загрузка видео | `videos.insert` (scope `youtube.upload`) | **проекты API, созданные после 28.07.2020 и не прошедшие аудит, загружают только в режиме «приватно»**; файл ≤ 256 ГБ |
| Квоты (с 01.06.2026 — «гранулярные корзины») | `videos.insert` и `search.list` — свои корзины по **100 вызовов в сутки** (1 единица за вызов); остальные методы — 10 000 единиц в сутки; сброс — полночь по тихоокеанскому времени | `videos.update`, `delete` — 50; `thumbnails.set` ≈ 50; `videos.list` — 1; `videos.batchGetStats` (с 03.06.2026) — своя корзина 10 000 |
| Метаданные | `videos.update`: название, описание, теги, категория, статус | 50 единиц |
| Обложка | `thumbnails.set` — JPEG/PNG, **до 50 МБ с 14.09.2026** (было 2 МБ) | свои обложки доступны каналу по правилам YouTube (подтверждение аккаунта — по справке; в этой сессии не перепроверено) |
| Отложенная публикация | `status.privacyStatus = private` + `status.publishAt` | дата в прошлом = сразу публично |
| Раскрытие ИИ | `status.containsSyntheticMedia` (с 30.10.2024) | наши композиции (Д11) и настоящий рендер — не синтетика |
| Shorts | отдельного признака в API нет — Shorts определяется самим видео (вертикальное/квадратное, короткое) | — |
| Плейлисты | `playlistItems.insert` (50) | — |
| Статистика | Data API — `viewCount` и др. (с 27.08.2026 публичный просмотр считается с первого кадра); **YouTube Analytics API** (запросы отчётов) и **Reporting API** (массовые отчёты) — OAuth, scope `yt-analytics.readonly` | Д15: пока ручной импорт |
| OAuth | OAuth 2.0 с refresh token | при статусе приложения «Testing» refresh token **живёт 7 дней**; не больше 100 refresh token на аккаунт и клиент |

**Вывод.** YouTube — **полуавтоматизация**: правка описания,
названия, обложки, плейлистов и отложенная публикация уже
загруженного видео — через API; **загрузка** публично — только после
аудита проекта Google (до этого — «приватно», автор открывает
вручную). Для автора это и есть нормальный путь: видео монтирует и
загружает он сам, система готовит метаданные и обложку и может
обновлять их по одобрению. Приложение в статусе «Testing» требует
повторного входа раз в 7 дней — учесть в `docs/operations/CREDENTIALS.md`.

## 4. Discord — вебхук, бот, сервер

Источники: discord.com/developers/docs/resources/webhook, …/resources/message,
…/topics/rate-limits, …/reference (загрузка файлов),
…/resources/guild-scheduled-event.

| Сущность | Что даёт | Ограничения |
|---|---|---|
| **Вебхук** (Incoming) | публикация в один канал без бота и без OAuth: `Execute Webhook`; правка и удаление своих сообщений (`Edit/Delete Webhook Message`); `wait=true` возвращает созданное сообщение (id) | URL вебхука содержит токен — это **секрет**; в канал-форум нужно `thread_name` (создаст ветку) или `thread_id` |
| **Бот** | всё, что разрешено правами на сервере: сообщения, ветки, `Crosspost` в канале-объявлении (право `SEND_MESSAGES`/`MANAGE_MESSAGES`), события сервера | нужен токен бота и приглашение бота на сервер |
| **Аккаунт автора** | ручная работа | автоматизация пользовательского аккаунта (self-bot) запрещена правилами Discord |
| **Сервер** | каналы, роли, онбординг (`docs/platforms/DISCORD.md`) | существование сервера — UNKNOWN (ОР-6) |
| **Функции сообщества** | события (`Create Guild Scheduled Event` — не больше 100 активных/запланированных), каналы-объявления, форумы | события — через бота с правами |

| Лимит | Значение |
|---|---|
| Текст сообщения | до 2000 знаков |
| Embed | до 10 в сообщении; title 256, description 4096, полей 25, сумма текстов всех embed ≤ 6000 |
| Файл | по умолчанию **20 МиБ** на файл (больше — по Nitro или уровню буста сервера) |
| Глобально | 50 запросов/с на бота |
| По маршрутам | заголовки `X-RateLimit-*`, «лимиты не хардкодить» |
| Неверные запросы | 10 000 ответов 401/403/429 за 10 минут → временная блокировка IP |

**Вывод.** Discord — **полная автоматизация** объявлений через
вебхук (без бота), но **заблокировано ОР-6**: сервер не подтверждён.
Бот нужен только для кросспоста объявлений и событий — позже.

## 5. GitHub — REST/GraphQL, вебхуки, токены

Источники: docs.github.com/en/rest/releases/releases,
…/rest/using-the-rest-api/rate-limits-for-the-rest-api,
…/pages/getting-started-with-github-pages/what-is-github-pages,
…/github-pages-limits.

| Что | Как | Ограничения |
|---|---|---|
| Релизы | REST `POST /repos/{owner}/{repo}/releases` (+ правка, удаление, ассеты) | нужен push-доступ; fine-grained PAT, токен GitHub App (установки или пользователя) с правом `Contents: write`; если коммит релиза меняет `.github/workflows/` — нужно право на workflows |
| Обсуждения | GraphQL (`createDiscussion`) | включены в репозитории |
| Issues, README | REST (Contents API — коммит файла) | README профиля — это коммит в `dpsmpx/dpsmpx` (правка профиля — автор, Д12) |
| События | вебхук `release` и др. на публичный адрес | у статического сайта приёмника нет → опрос API (`GET …/releases/latest`) из локального запуска (`SYSTEM_DESIGN.md`, §3) |
| Лимиты | без токена — 60 запросов/ч по IP (только публичные данные); с токеном — 5000/ч; вторичные: ≤ 100 одновременных, ≤ 900 «очков» в минуту на REST | — |
| Pages | бесплатно — только публичные репозитории (закрытые — GitHub Pro и выше); рекомендованный предел 1 ГБ; «не для коммерческого хостинга» | — |

**Особенность автора.** Galdhold и DPlang — закрытые репозитории (Д17):
их релизы не видны публике, а сырые данные GitHub не публикуются
(§37 постановки). GitHub для системы — **источник фактов** (теги,
релизы, вехи → `data/releases/`, `facts.yaml` после проверки
человеком) и площадка для **открытых** проектов и README профиля.

**Вывод.** GitHub — **полная автоматизация** технически (релизы
открытых репозиториев), но по смыслу — источник истины о софте, а не
соцсеть: публикация туда — только release notes открытых проектов и
README профиля по одобрению.

## 6. TikTok — Content Posting API

Источники: developers.tiktok.com/doc/content-posting-api-get-started,
…/doc/content-sharing-guidelines.

- Прямая публикация (Direct Post) — через приложение с OAuth автора.
- **Клиенты без аудита публикуют только в `SELF_ONLY`** (приватно);
  открыть публично — владелец аккаунта вручную. Плюс лимиты: число
  активных авторов в сутки и постов на аккаунт (около 15 в сутки).
- Аудит — заявка в TikTok с описанием использования.

**Вывод.** TikTok — **ручное одобрение площадкой** (аудит); до него —
ручная публикация автором по пакету (Д19 не меняется).

## 7. Что следует для архитектуры

1. **Матрица возможностей — данные, а не код**: при смене API
   правится `data/platforms/capabilities.yaml`, а не модель контента.
2. **У каждой площадки — ручной путь** (пакет: текст, медиа, адресат,
   чек-лист); адаптер API — улучшение, а не условие публикации.
3. **Идемпотентность — своя.** Нативная есть только у VK (`guid`, 1
   час); Telegram и Discord-вебхук дублируют молча — журнал публикаций
   и запрет слепого повтора после неизвестного исхода (Д24).
4. **Лимиты — в адаптере**, у каждой площадки свои (Telegram — 1/с в
   чат и `retry_after`; Discord — заголовки маршрутов; YouTube — суточные
   корзины; VK — ошибка 6 и капча).
5. **Учётные данные разной природы**: бессрочный токен бота, URL
   вебхука-секрет, ключ VK на 1 час, OAuth Google с refresh token на 7
   дней в «Testing» — ротация по площадке (`docs/operations/CREDENTIALS.md`).
6. **Статистика через API** — у YouTube и VK есть, у Telegram и Discord
   нет. Пока действует Д15 (ручной импорт); пересмотр — фаза 10.
