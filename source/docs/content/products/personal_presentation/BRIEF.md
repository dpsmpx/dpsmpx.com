# Бриф: презентационное изображение автора (CI-0001)

Первый продукт системы (фаза 1, `ROADMAP/ROADMAP.md`). Шаблон —
`templates/content_brief.md`. Объект —
`content/items/CI-0001-personal-presentation/item.yaml`.

| Поле | Значение |
|---|---|
| Объект | CI-0001, тип `presentation_card`, опора PERSON |
| Цель | За 2–3 секунды показать, кто такой dpsmpx: человек, который строит сложные нативные системы — игру, движок и язык — с ИИ как инструментом и сам принимает архитектурные решения; за этим есть настоящий результат. |
| Аудитории | **профессиональная** (главная: оценивает уровень и системность — нужны метод и проверяемый масштаб); **соавторы** (порядок и роль человека); **разработчики** и **разработчики с ИИ** (как устроена работа с ИИ). Игрокам изображение не адресовано — для них снимки игры (опора PROJECT). |
| Площадки и форматы | GitHub — `github_social` 1280×640, EN (баннер README профиля); YouTube — `youtube_banner` 2560×1440 с безопасной зоной, RU (шапка канала); Telegram — `telegram_post` 1280×720, RU (закреплённая запись-вход канала-дневника, IC-09); VK — `vk_post` 1280×720, RU (требования не подтверждены — `verified: false`); мастер — 2560×1440, RU и EN. Не делаются: Discord (ОР-6), TikTok (у профиля нет шапки; аватар — ОР-10), обложка видео (нет видео). |
| За 2–3 секунды | лицо автора → имя `dpsmpx` → роль «Разработчик нативных систем» → цепочка «человек решает — ИИ реализует — проверено». |
| Ключевое сообщение | «Строю сложные нативные системы — с ИИ как инструментом; архитектура и решения — мои.» (`CONTENT_STRATEGY.md`, §1) |
| Утверждения | AU-HANDLE (имя), AU-ROLE (роль), AU-METHOD (ИИ пишет, решения и приёмка — автора; ворота «приёмку решаю я»), AU-MEMORY (узел Git — память проекта), ME-NO-CI (узел «Проверка», а не «CI»), GH-NAME, GH-GENRE, GH-TECH (плашка Galdhold), GH-ENGINE (слово «движок»), DP-WHAT (слово «язык»), GH-LOC, GH-CHECKS (числа с датой «10.2026»), GH-COMMITS (приёмка слияний). Для варианта B ещё GH-ANDROID и GH-RELEASE-PLAN. |
| Чего не говорить | «CI» (CL-CI), «open source/source available» (CL-OPEN-SOURCE), «работает на Windows» (CL-WINDOWS-RUNS), старые числа строк (CL-STALE-LOC), ускорение «в N раз» (AH-SPEEDUP), оценки ИИ (AH-AI-PRAISE), «с нуля за N дней» (CL-FROM-ZERO), VoxelRPG без «прежде» (CL-OLD-NAME). Число без факта в реестре — нельзя. |
| Визуальные требования | Иерархия `VISUAL_SYSTEM.md`, §4: человек → имя и роль → инженерный контекст → ИИ → доказательство → декор. Не больше 4 групп текста и 3 размеров. Портрет — только A-001 (Д10, Д18): кадрирование и тон; интерьер затемнён до нечитаемости. Цвета и шрифты — `assets/brand/tokens.json`. Нет «ИИ-эстетики» (Д9), нет кода закрытых проектов (Д17). |
| Ограничения | Имя — только `dpsmpx`, настоящее имя не добавляется (ОР-1; **обновление 04.10.2026:** ОР-1 решён — Д20, имя рядом с `dpsmpx`; подпись пересматривается на ревизии; **05.10.2026 Д20 отменено — Д40: имени нет нигде**). Публикация с портретом — после утверждения автором (Д18, гейт Brand) и решения ОР-1. Права фотографа A-001 подтверждает автор (гейт Legal). Публикует автор (Д12). |
| Варианты | Четыре, каждый проверяет гипотезу о том, что лучше выполняет цель: **A professional** — человек + метод + два доказательства (баланс для профессиональной аудитории); **B technical** — схема с воротами и три числа (сильнее ли инженерная подача); **C cinematic** — портрет и одна фраза (хватает ли образа без доказательств); **D minimal** — без лица (держится ли знак без человека; запасной для мест, где лицо не нужно). |
| Критерии успеха | Communication и Identity fit ≥ 4 у выбранного варианта; ни одного fatal; гейты Factual, Visual, Platform, Safety, Provenance — `pass` по `tools/check.sh`; на миниатюре (≈ 320 px по ширине) читаются лицо, имя и роль; интерьер не читается. |
