# Модель качества

Контент проверяется по пяти независимым осям ценности — **Factuality,
Brand consistency, Platform fitness, Visual/content quality, Strategic
usefulness** — через гейты (обязательные условия) и оценки (сравнение
вариантов). Один общий балл не используется.

## 1. Гейты

Статусы: `pass`, `fail`, `pending`, `n/a`. Для `APPROVED` все гейты —
`pass` или `n/a` (с причиной).

| Гейт | Условие | Проверяет | Автоматически (`tools/check.sh`) |
|---|---|---|---|
| **Factual** | каждое значимое утверждение — `FACT` из реестра с `public: true`; нет запрещённых формулировок; числа не просрочены (`recheck_by`) | сессия | ссылки `claims` на реестр; класс и `public`; `forbidden.yaml` по всем текстам объекта; просрочка `recheck_by` — предупреждение |
| **Brand** | совпадает с идентичностью (`IDENTITY.md`) и визуальной системой; автор — только `dpsmpx`, имени нет (Д40); портрет — по Д10/Д18 | сессия готовит, **автор утверждает** | токены цвета и шрифты композиции — из `assets/brand/tokens.json`; портрет — только из `REFERENCE_IMAGE` |
| **Visual** | технически качественно: читаемость на целевом размере, контраст, иерархия, без артефактов | сессия | минимальный размер текста в пикселях каждого формата; контраст WCAG (≥ 4,5 обычный текст, ≥ 3 крупный); число текстовых элементов ≤ предела |
| **Platform** | формат по `export_specs.yaml`; смысловые элементы в безопасной зоне; текст по шаблону площадки | сессия | размеры, тип и вес файлов; лицо, имя и роль — внутри `safe_area` (по координатам из рендера) |
| **Safety** | нет нежелательного: личные данные, интерьер, документы, экран с перепиской, геометки, чужие лица | сессия | нет метаданных EXIF/XMP в экспорте |
| **Legal** | права на всё: фото, шрифты, иконки, логотипы, снимки (`docs/legal/RIGHTS_MATRIX.md`) | сессия; автор — права фотографа | шрифты — из разрешённого списка; нет внешних URL в композиции |
| **Provenance** | происхождение всех входов и выходов записано | сессия | каждый вход есть в `docs/PROVENANCE.md`/`provenance.yaml`; хэши совпадают |

## 2. Оценки вариантов (0–5)

| Ось | 0 | 3 | 5 |
|---|---|---|---|
| Factuality | неверное утверждение | верно, но без даты/контекста | всё из реестра, с датой, без двусмысленности |
| Identity fit | не про автора или чужой стиль | узнаваемо частично | однозначно dpsmpx: голос, визуальный язык, позиционирование |
| Visual quality | брак (обрезки, нечитаемо) | аккуратно, но без силы | ясная иерархия, читаемо на миниатюре, ни одного лишнего элемента |
| Communication | смысл не считывается | считывается после изучения | цель понятна за 2–3 секунды |
| Platform fit | не подходит формату | подходит после доработки | родная форма для площадки |
| Strategic value | вредит позиционированию | нейтрально | двигает главный нарратив (Д4) и цель объекта |

Оценки ставятся **по цели объекта**, а не «вообще». Каждая — с одной
фразой обоснования.

## 3. Проблемы

- **fatal** — блокирует: ложное утверждение, нарушение прав, личные
  данные, искажение внешности, запрещённая формулировка `fatal`.
- **major** — исправить или обосновать до `APPROVED`: нечитаемый текст,
  смысловой элемент вне безопасной зоны, иерархия перевёрнута, устаревшее
  имя.
- **minor** — по желанию: оттенок, отступ, порядок слов.

## 4. Ревью

1. Генерирующая сессия — автоматические проверки (`tools/check.sh`).
2. Критика — отдельный проход по `prompts/critique/` (свежий контекст или
   отдельный агент только для чтения): оценки, проблемы, рекомендация.
3. Ревизия — исправить fatal/major, записать, что изменено.
4. Автор — гейт Brand и `approval`.

## 5. Выбор

Выбирается **не самое красивое, а то, что лучше всего выполняет цель**.
Порядок сравнения:

1. Отсечь варианты с fatal и с непроходимым гейтом.
2. Сравнить по оси, которая прямо выражает цель объекта (у
   презентационного изображения — Communication и Identity fit).
3. При равенстве — Strategic value, затем Platform fit.
4. Visual quality решает только при равенстве всего остального.

Решение — в `DECISION.md` продукта: выбранный вариант, почему, почему не
остальные, что известно о рисках.

## 6. Готово к публикации

Объект готов, когда: состояние `EXPORTED`; все гейты `pass`/`n/a`;
`approval.by: author`; `tools/check.sh` зелёный; у каждой площадки — свой
экспорт и свой текст (вариант `variants/<площадка>.<язык>.md`, одобренный
автором), а не копия одного.
