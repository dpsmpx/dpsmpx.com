# Эксперименты и обратная связь

Решения Д14 (вариация — не эксперимент) и Д15 (метрики — ручной
импорт). Схемы — `schemas/experiment.schema.json`,
`schemas/metrics.schema.json`; данные — `data/experiments/`,
`data/metrics/`. Реализация — фаза 6 (`ROADMAP`); модель и проверки
формата — уже сейчас.

## 1. Вариация и эксперимент

| | Вариация | Контролируемый эксперимент |
|---|---|---|
| Зачем | выбрать лучший вариант до публикации | узнать, что работает у аудитории |
| Решает | критика по цели + автор | данные площадки |
| Где | `variants[]` объекта | `data/experiments/EXP-NNNN.yaml` |
| Нужны | цель объекта | гипотеза, метрика, площадка, длительность, критерий решения — **до запуска** |

Выбор по вкусу, записанный как «тест», — ложное знание (Д14).

## 2. Эксперимент

```
Experiment
├── id                 EXP-NNNN
├── item               CI-NNNN
├── hypothesis         «Обложка с лицом автора и игрой даст больше времени просмотра, чем снимок меню»
├── variants           [A, B] — id вариантов объекта
├── audience           кто видит (площадка решает распределение)
├── platform           youtube (Test & Compare) | telegram | …
├── metric             watch_time_share | ctr | views | retention | reactions | subscriber_conversion
├── min_sample         минимум показов до вывода (у малых каналов — иначе «нет вывода»)
├── started, ended
├── result             цифры по вариантам + ссылка на выгрузку в data/metrics/
└── decision           что меняем; или «нет вывода» с причиной
```

Правила:
- Гипотеза и метрика записываются до запуска; менять их по ходу нельзя.
- Варианты различаются одним заметным признаком; слишком похожие
  варианты YouTube тестирует долго и без победителя.
- Малые выборки (сейчас — 84 подписчика YouTube, 5 — канала) часто не
  дают вывода; «нет вывода» — допустимый результат.
- Площадочный A/B решает по своей метрике: YouTube Test & Compare —
  по доле времени просмотра, не по CTR.
- Проверка доверия: если площадка показывает распределение показов
  между вариантами, сильный перекос от задуманного — признак сбоя
  (sample ratio mismatch), а не победы.

## 3. Метрики

Загружаются выгрузкой из аналитики площадки (CSV) — без скрейпинга и без
токенов (Д15):

```sh
python3 -m tools.cs metrics import --item CI-0001 --platform youtube \
    --variant A --file ~/Downloads/youtube_export.csv
```

Нормализованная запись (`data/metrics/<item>/<platform>-<date>.yaml`):

```
item, variant, platform, publication_url, period {from, to}, source_file_sha256,
values: impressions, ctr, views, watch_time_hours, avg_view_duration_s,
        retention_30s, reactions, comments, shares, subscribers_gained, clicks
```

Неизвестная колонка не угадывается — сохраняется в `unmapped` и
перечисляется в выводе импорта.

## 4. Петля обратной связи

```
публикация → метрики (импорт) → сводка по опорам/форматам/площадкам →
наблюдение (FACT о своей аудитории, с датой) → решение (DECISIONS) →
обновление стратегии и шаблонов
```

- Вывод о «том, что работает» — только из своих данных; рекомендации
  площадок — вход, а не закон (§34 постановки).
- Не писать «так любит алгоритм», пока нет данных.
- Наблюдения о своей аудитории — в `facts.yaml` с `subject: audience`.
