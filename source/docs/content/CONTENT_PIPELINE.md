# Конвейер контента

Этапы от намерения до архива. Каждый этап — вход, выход, кто отвечает,
проверка и условие провала. Состояния объекта — `CONTENT_MODEL.md`, §2;
канон и варианты площадок (v2) — `CANONICAL_MODEL.md`; производственный
конвейер публикации — `PUBLISHING.md`, §1.

«Сессия» — сессия ИИ в этом репозитории; «автор» — dpsmpx.

| Этап | Вход | Выход | Кто | Проверка | Провал, если |
|---|---|---|---|---|---|
| **00_research** | намерение автора | заметки и источники в `docs/research/` или в брифе; новые факты — в `facts.yaml` | сессия | у новых фактов есть источник и дата | факт без источника; догадка вместо `UNKNOWN` |
| **01_identity** | `docs/identity/`, `AUTHOR_MASTER_CONTEXT.md` | подтверждение, что объект не меняет идентичность (или запись в `DECISIONS.md`) | сессия; изменение — автор | нет расхождения с решениями | объект молча меняет имя, позиционирование, визуальный язык |
| **02_strategy** | `CONTENT_STRATEGY.md`, `docs/platforms/` | `item.yaml`: pillar, objective, audiences, platforms → `IDEA` → `RESEARCHED` | сессия | `validate.py` | нет цели; площадка не подходит опоре |
| **03_brief** | объект `RESEARCHED`; `templates/` | бриф (`templates/content_brief.md`) → `BRIEFED` | сессия, автор при желании | бриф отвечает на все поля шаблона | бриф без цели, аудитории или критериев успеха |
| **04_draft** | бриф | творческое направление, спецификация композиции/текста по вариантам (`spec/`) | сессия | варианты различаются по цели, а не по вкусу | вариант не обоснован целью |
| **05_generation** | спецификации; промпт `prompts/…` нужной версии | рендеры или тексты всех вариантов (`renders/`) → `GENERATED` | сессия (инструмент) | рендер воспроизводим из спецификации; записан метод и версия промпта | ручная правка вне спецификации; нет записи метода |
| **06_critique** | рендеры | критика: оценки 0–5 по шести осям, fatal/major/minor (`templates/critique.md`) → `UNDER_REVIEW` | сессия (отдельным проходом) | у каждого варианта оценки и проблемы | критика без осей; «нравится» вместо оценки по цели |
| **07_revision** | критика | исправленные спецификации и рендеры → `REVISED` → снова `UNDER_REVIEW` | сессия | каждая исправленная проблема отмечена | major/fatal остались без исправления или обоснования |
| **08_verification** | лучший вариант | гейты Factual, Brand, Visual, Platform, Safety, Legal, Provenance (`QUALITY_MODEL.md`) | сессия — автоматические; автор — Brand и утверждение | `tools/check.sh` зелёный; гейты `pass` | любой гейт `fail` |
| **09_selection** | варианты после гейтов | `selected_variant` + решение (`DECISION.md`); `approval` автора → `APPROVED`. Текстовый объект v2 (канон без вариантов-изображений, например статья) — без `selected_variant`: выбор — одобренный автором вариант каждой площадки (Д12, Д22) | автор | выбран вариант, лучше всех выполняющий цель | выбор «самое красивое» без связи с целью; нет согласия автора |
| **10_export** | утверждённый вариант | файлы по форматам `export_specs.yaml`, хэши → `EXPORTED` | сессия (инструмент) | размеры, вес, безопасные зоны | ручное масштабирование; формат без источника требований |
| **11_publication** | экспорт; варианты `variants/` с одобрением автора | публикация через движок (`docs/content/PUBLISHING.md`) или вручную (Д33); запись в журнал → `PUBLISHED` | **одобряет и запускает рабочую публикацию только автор** (Д12) | запись `publication` | публикация не из `EXPORTED`; версия не одобрена или изменена после одобрения |
| **12_archive** | опубликованный объект; метрики (фаза 6) | метрики в `data/metrics/`; выводы; → `ARCHIVED` | сессия готовит, автор решает | метрики связаны с объектом и вариантом | выводы без данных («так любит алгоритм») |

## Правила конвейера

- Этапы не пропускаются; возврат назад — разрешён (ревизия, новый
  бриф) и записывается в историю.
- Каждый переход состояния — строка в `history` с датой и смыслом.
- Сессия, которая генерировала, не должна быть единственным критиком:
  критика — отдельным проходом по чек-листу (`prompts/critique/`),
  утверждение — автор.
- Объект, ждущий автора, отмечается в `TODO.md` («за автором») и
  `docs/session/HANDOFF.md`.
