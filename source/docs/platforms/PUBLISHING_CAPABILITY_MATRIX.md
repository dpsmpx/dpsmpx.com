# Матрица возможностей публикации

Что каждая площадка позволяет делать через официальный API **для
аккаунтов автора** на дату проверки (Д33; постановка, §3). Не все
площадки поддерживают одинаковую автоматизацию: уровень задаёт площадка,
а не наш код. Одобрение автора нужно на любом уровне (Д12).

**Как обновлять.** Сменился API или условия доступа — правится
`data/platforms/capabilities.yaml` (с источником и датой), затем
`python3 -m tools.cs capabilities --write` переписывает таблицу ниже;
проверка `capabilities` в `tools/check.sh` ловит расхождение таблицы,
данных и адаптеров. Архитектура при этом не меняется (§69).

## Уровни

| Уровень | Что значит для автора |
|---|---|
| **FULLY_AUTOMATED** | официальный API делает публикацию, правку и удаление для нашего типа аккаунта без допуска площадки; система публикует одобренную версию сама |
| **SEMI_AUTOMATED** | часть операций — через API (метаданные, обложка, отложенный выпуск), часть — вручную (загрузка видео) |
| **MANUAL_APPROVAL_REQUIRED** | API есть, но доступ даёт площадка: запрос в поддержку (VK — право `wall`), аудит приложения (TikTok, публичная загрузка YouTube). До допуска — ручной путь |
| **MANUAL_ONLY** | подходящего официального API для этого аккаунта нет (личный профиль Telegram) |
| **UNSUPPORTED** | операция невозможна ни через API, ни разумным ручным путём |

Знаки в ячейках: ✓ API — делает официальный API; ◐ по допуску — API есть,
доступ выдаёт площадка; ● своя система — делает наша система (сайт,
планировщик); ✋ вручную — только в интерфейсе площадки; ✗ — нельзя.

## Ручной путь (Д33)

Для каждой площадки система готовит **пакет публикации**: текст в
разметке площадки, медиа нужного формата, адресат и чек-лист —
`python3 -m tools.cs preview <объект|кампания>`. Автор публикует сам,
затем записывает адрес в журнал:

```sh
python3 -m tools.cs publish CI-0001 vk.ru --to vk-author --record-manual --url https://vk.com/wall…
```

Так журнал и сводка кампании остаются полными и для площадок без API.

## Что меняется дальше

- **Telegram** — подключение бота к каналу (`docs/operations/CREDENTIALS.md`),
  затем безопасный режим на тестовом канале и первая рабочая публикация
  (фаза П4, `ROADMAP/ROADMAP.md`).
- **VK** — сначала решение автора «страница или сообщество» и запрос
  права `wall`; без него — ручной путь (П5).
- **YouTube** — метаданные и обложки через API после OAuth (П7); загрузка
  остаётся ручной, пока проект не прошёл аудит Google.
- **Discord** — после ОР-6; вебхук даёт полную автоматизацию объявлений (П6).
- **GitHub** — релизы открытых репозиториев и источник фактов (П8).
- **TikTok** — только после аудита клиента API; до этого ручной путь.

Исследование и источники — `docs/research/publishing/PLATFORM_APIS.md`.
