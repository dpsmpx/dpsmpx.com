# Промпт: критика визуальной работы, версия 1

Отдельный проход критики (этап 06_critique, `docs/content/QUALITY_MODEL.md`,
§4): свежий контекст или агент только для чтения — не та сессия, что
генерировала. Результат — по шаблону `templates/critique.md`.

## Вход

- `item.yaml` объекта: цель, аудитории, площадки, утверждения.
- Бриф и творческое направление продукта.
- Рендеры вариантов (`renders/`) — смотреть сами файлы, не описания.
- Вывод `python3 -m tools.cs check claims visual` по объекту.

## Чек-лист — для каждого варианта

1. **Цель за 2–3 секунды.** Что считывается первым, вторым, третьим?
   Совпадает ли с иерархией (человек → имя/роль → метод → доказательство)?
2. **Миниатюра.** Уменьшить мысленно до ≈ 320 px по ширине: читаются ли
   лицо, имя, роль?
3. **Факты.** Каждая фраза с утверждением — в `claims` спецификации?
   Есть ли двусмысленность (фраза, которую можно прочесть как
   неверный факт)?
4. **Запреты и тон.** Превосходные степени, «ИИ-эстетика», хвастовство,
   оценки ИИ?
5. **Портрет.** Черты не изменены? Читается ли интерьер (обои, окно,
   предметы) — где именно?
6. **Текст.** Мелкий, обрезанный, наложенный, слишком много групп?
7. **Площадки.** Подходит ли композиция каждому формату брифа (шапка с
   безопасной зоной, 2:1 GitHub, 16:9 лента)?
8. **Бренд.** Цвета и шрифты из токенов; знак `dpsmpx.`; проект — «в
   рамке», не перекрашен.
9. **Имя.** Автор — только `dpsmpx`: ни настоящих, ни выдуманных имени
   и фамилии автора на изображении и в alt (Д40) — любое такое слово
   fatal. Текст на картинках проверки не читают — это пункт критика.

## Оценки и проблемы

Шесть осей 0–5 (`QUALITY_MODEL.md`, §2) — по цели объекта, с одной
фразой обоснования. Проблемы — fatal / major / minor с id
`<вариант>-<n>` (например, `A-1`) и местом на изображении.
