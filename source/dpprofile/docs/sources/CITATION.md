# Правила цитирования и датирования

Как факт ссылается на источник и какую дату он несёт. Форму ссылок
проверяет `tools/verify/check_facts.py`, их соответствие клонам
источников — `tools/verify/check_refs.py` (полный прогон).

## Что считается источником

Только источник из `docs/sources/REGISTRY.md`:

- репозиторий автора на GitHub — коммит, файл на коммите, релиз;
- публичная страница (GitHub, Steam и т. п.) — с датой наблюдения;
- датированная заметка `N-NNNN` в `docs/sources/NOTES.md` с указанием
  происхождения: что наблюдалось, когда, каким способом и как это
  перепроверить. Слова автора в сессии — тоже заметка, с датой и
  пометкой «слова автора».

Не источник: память агента, догадка, «известно, что», пересказ без
места, чужой пересказ источника автора.

## Ссылки

| `source_type` | Источник в реестре | Форма `ref` | Пример |
|---|---|---|---|
| `commit` | `repo` или `self` | полный SHA, 40 знаков | `758804f998e45556f9338e8f6fb80e9aa339a85b` |
| `file` | `repo` или `self` | `путь@SHA` — файл на конкретном коммите | `docs/direction/DECISIONS.md@f2ba263fa06265432066aa161129a6b532479bed` |
| `release` | `repo` | `тег@SHA` — коммит, на который тег указывал в день наблюдения | `v22.09.26@8dc7a988986422530ddc45d64ad7cf7a822122f9` |
| `url` | `site` | адрес, начинающийся с `https://` и адреса источника из реестра | `https://store.steampowered.com/search/?term=Galdhold` |
| `note` | любой | `N-NNNN` — заметка о том же источнике | `N-0001` |

- Файл всегда привязан к коммиту: файлы меняются, коммиты — нет.
- Тег может переместиться; поэтому рядом с тегом — SHA на день
  наблюдения. Перемещение тега позже — не ошибка факта.
- Страница может измениться или исчезнуть; факт с `url` говорит о том,
  что было видно в день `observed`.
- Решения других репозиториев — с префиксом: `Galdhold:Р12`,
  `DPpass:D-24`. Голые `D-NN` в этом репозитории — только свои решения.

## Даты

`date` — дата события или состояния, о котором факт:

- `commit` — дата коммитера: `git log -1 --format=%cs <SHA>` (в часовом
  поясе, записанном в коммите). Это дата, записанная в коммите; её
  ставит тот, кто коммитит, поэтому формулировка говорит «коммит
  датирован», а не «работа сделана тогда». `check_refs.py` сверяет её
  с клоном.
- `file` — дата события, которую называет сам файл (например, дата
  решения автора в журнале решений). Если файл даты не называет —
  дата коммита, на который ссылается `ref`, и формулировка «на коммите
  … в файле …». В обоих случаях не позже даты этого коммита.
- `release` — дата публикации релиза на GitHub (UTC), какой она видна в
  день наблюдения; не раньше даты коммита тега.
- `url` — дата наблюдения, если страница не называет дату события.
- `note` — дата события из содержимого заметки; если его там нет — дата
  наблюдения заметки.

`observed` — когда тот, кто записывает факт, проверил источник. Факт не
бывает о будущем: `date` не позже `observed`. План записывается как
факт о записи плана (`docs/direction/SCOPE.md`, «Не входит»).

## Формулировка

- Одно предложение до 300 знаков (D-05); короткий SHA (7 знаков) в
  тексте, полный — в `ref`.
- Цитата — в «ёлочках», короткая; больше одной фразы не цитируется.
- `basis: stated` — формулировка называет, где записано утверждение:
  «В `DECISIONS.md` Galdhold (Р20) записано: …». Сам факт тогда — то,
  что так записано, а не то, что так было.
- Числа — как в источнике или как их выдаёт названная команда git; без
  округлений «около», «более».

## Доступ к источникам

Часть репозиториев автора закрыта (`docs/sources/REGISTRY.md`, столбец
«Доступ»): их факты перепроверяет только владелец или тот, кому он дал
доступ. Из закрытых источников сюда не переносится ничего, кроме
идентификаторов и выжимок (D-05).

## Особые случаи

- README репозитория Galdhold не используется как источник фактов о
  состоянии проекта: по правилу самого репозитория он не источник истины
  (`CLAUDE.md` Galdhold, раздел «README.md»; место — `docs/sources/MAP.md`).
  Состояние берётся из журнала решений, планов, файлов и истории.
- Дата первого коммита — это дата первой записи в истории репозитория,
  а не дата начала работы над проектом: в первый коммит может попасть
  уже готовый код (`docs/timeline/GAPS.md`).
