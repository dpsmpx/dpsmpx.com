## Правила плана

- Состояние этапа — `выполнен (YYYY-MM-DD)`, `в работе` или `—`; в
  таблице и в файле этапа (строка «Состояние: …») оно одно и то же.
- Этап «в работе» — ровно один, пока не выполнены все; все этапы до
  него выполнены, все после — `—`.
- Этап меняет только то, что в нём записано; найденное попутно — в
  `TODO.md`, если относится к текущему этапу, иначе — в файл своего
  этапа.
- У каждого критерия выхода есть машинное условие
  `<!-- gate: … -->`. Отметка `[x]` при ложном условии — ошибка. У этапа
  «в работе» истинное условие без отметки `[x]` — тоже ошибка: отметка
  ставится в том же коммите, что выполнила условие. Критерии этапов
  `—` отмечаются, когда этап начинается.
- Этап «выполнен» — только когда отмечены все его критерии.
- Раздел состояния в `README.md` строится из этого плана
  (`tools/verify/readme_status.py`, D-10).

## Условия критериев

Условие — один или несколько термов через ` & `.

| Терм | Истинен, когда |
|---|---|
| `file:ПУТЬ` | файл есть в репозитории |
| `check:ИМЯ` | есть `tools/verify/ИМЯ.py` и `tools/verify/run.sh` его вызывает |
| `count:ЧТО>=N` | в репозитории не меньше N: `facts` (активных фактов), `insights` (активных выводов `I-`), `hypotheses` (активных гипотез `H-`), `sources`, `notes`, `timeline` (строк хронологии), `decisions` (принятых решений) |
| `coverage:sources` | у каждого тега `docs/direction/SCOPE.md` есть источник из реестра |
| `coverage:facts` | у каждого тега есть активный факт |
| `coverage:areas` | в каждой области (`project`, `process`, `result`) есть активный факт |
| `coverage:timeline` | каждый тег встречается среди фактов хронологии |
| `coverage:outline` | каждый пункт `docs/book/OUTLINE.md` ссылается на факт, вывод или гипотезу |
| `coverage:method` | каждая строка таблицы `docs/method/METHOD.md` ссылается на вывод `I-NNNN` |
| `stable:ПУТЬ>=ДНЕЙ` | файл не менялся в git не меньше ДНЕЙ дней и не изменён в рабочей копии; без истории git (копия) или в неглубоком клоне, где граница клона выглядит правкой файла, условие не проверить — у отмеченного критерия пометка с причиной, в полном прогоне (`--strict`) — ошибка |
| `decision-mark:МЕТКА` | есть принятое решение с этой меткой |
| `fact-mark:МЕТКА` | есть активный факт с этой меткой |
| `status:ПОЛЕ=ЗНАЧЕНИЕ` | поле блока `book-gate` в `docs/book/STATUS.md` равно значению |

Суждение автора, которое машина проверить не может, оформляется
решением с меткой (`decision-mark:`), а не отметкой без условия.
