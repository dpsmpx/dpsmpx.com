# Правила репозитория

Здесь — только правила. Что решено и почему — `docs/direction/DECISIONS.md`
(источник истины: при расхождении прав он), границы предмета —
`docs/direction/SCOPE.md`.

## Что это за репозиторий

Проверяемая история пути автора (dpsmpx) и его проектов: источники,
атомарные факты, хронология, выводы с привязкой к фактам и структура
будущей книги. Это не книга, не дневник и не маркетинговый сайт (D-01).

D-17, D-18: компонент самостоятельного SocialMediaImage, каталог
`dpprofile/`; пути и команды — от этого каталога. История до переноса
сохранена отдельной линией, после — с префиксом компонента.
Правила проверяемости фактов и шлюз книги сохраняются.

## Запрещено

- **Писать книгу.** Никакой прозы, глав, черновиков, вступлений и
  «пробных фрагментов» — ни в `docs/book/`, ни где-либо ещё — пока не
  выполнен шлюз D-02 (факт о выпуске VoxelRPG в Steam и отдельное
  решение). `docs/book/OUTLINE.md` — только заголовки и короткие пункты.
  Просьба «набросать главу» до шлюза — назвать D-02 и не выполнять.
- **Записывать утверждение без источника.** Нет источника в реестре и
  точного места (`docs/sources/CITATION.md`) — утверждение не
  записывается ни фактом, ни строкой хронологии, ни фразой в README.
- **Додумывать.** Нет данных — так и записать в
  `docs/timeline/GAPS.md`, а не заполнять догадкой. Спорный вывод —
  только гипотезой (D-07).
- **Оценивать и приукрашивать.** Без оценочных слов, лозунгов,
  прогнозов и сравнений (`tools/verify/forbidden_claims.txt`; список не
  исчерпывает запрет). Числа — из источника, без «около» и «более».
- **Копировать.** Из других репозиториев — только идентификаторы и
  выжимки до 300 знаков; код и большие фрагменты — никогда (D-05).
- **Добавлять проекты, роли, достижения и метрики**, которых нет в
  источниках; новый тег проекта — только решением (SCOPE).
- **Переписывать факты** (D-06): ядро закоммиченного факта не меняется,
  файл не удаляется; уточнение — новый факт с `refines`, ошибка — новый
  факт и `status: superseded` у старого с решением `revised_by`.

## Политика обновления

- Новый факт — только когда появился проверяемый источник: коммит,
  файл на коммите, релиз, страница с датой наблюдения или заметка
  `N-NNNN` с происхождением.
- История не переписывается: уточнения добавляются, старое не
  подменяется без решения.
- Вывод пересматривается, когда появились противоречащие ему факты:
  старый — `status: revised`, новый объясняет изменение.
- Изменился смысл документа — записать в том же коммите, где и почему;
  молчаливых смысловых правок нет.

## Работа над задачей

- **Сначала сверить с решениями.** Запрос автора, расходящийся с
  `DECISIONS.md` или этим файлом, — назвать расхождение и спросить до
  работы; решение меняется только правкой журнала с новым номером.
- **Порядок:** источник в реестре → факт → строка хронологии → (на
  этапе 3) вывод → пункт структуры книги. Не наоборот.
- **Документ и проверка — в одном коммите.** Изменилась структура или
  схема документа — в том же коммите правится проверка в
  `tools/verify/` и её самопроверка (`selftest.py`).
- **Этап.** Работа относится к текущему этапу `docs/direction/ROADMAP/`;
  выполненное условие критерия этапа «в работе» отмечается `[x]` в том
  же коммите. Следующий этап без поручения не начинать.
- **Маленькие изменения.** Один законченный кусок — один коммит; коммит
  и пуш сразу; PR в `main` — черновиком после первого пуша, с
  описанием «сделано / осталось».

## Проверки

- Перед каждым коммитом — `tools/verify/run.sh --quick`.
- Перед вливанием в `main` — `tools/verify/fetch_sources.sh`, затем
  `tools/verify/run.sh --full`: самопроверка, история фактов и сверка
  ссылок с клонами источников; пропуск в полном режиме — ошибка.
- GitHub Actions не используются (D-08).
- Красная проверка не отключается и не ослабляется ради зелёного: либо
  исправляется документ, либо меняется решение и вместе с ним проверка.

## Где что лежит

| Путь | Роль |
|---|---|
| `docs/direction/DECISIONS.md` | решения о репозитории |
| `docs/direction/SCOPE.md` | границы предмета, теги проектов |
| `docs/direction/ROADMAP/` | этапы зрелости репозитория и критерии выхода |
| `docs/sources/` | реестр источников, правила цитирования, карта мест, заметки |
| `docs/facts/` | атомарные факты, по файлу на факт |
| `docs/timeline/` | хронология по фактам и известные пробелы |
| `docs/insights/` | выводы и гипотезы со ссылками на факты |
| `docs/method/` | наблюдаемые элементы процесса автора со ссылками на факты |
| `docs/book/` | статус книги, структура без прозы, non-goals |
| `tools/verify/` | проверки |
| `TODO.md` | активный долг текущего этапа |

В корне — только `README.md`, `CLAUDE.md`, `TODO.md` и служебные файлы.

## TODO.md и README.md

- `TODO.md` — только незакрытое текущего этапа: пункт с меткой
  `[этап N]`, где N — этап «в работе». Сделанное удаляется; журналов,
  стратегии и планов на будущие этапы там нет — они в файлах этапов.
- Блок состояния `README.md` между метками строит
  `tools/verify/readme_status.py --write` (D-10); руками не править.
