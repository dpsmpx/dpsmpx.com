Path

Where I come from and what system I'm heading for: the route by date and the goal as I wrote it down.

Route

  1. 2023

    Start

    A GitHub account and the first open projects: games, an editor and utilities in C++, Python and PascalABC.NET.

    Early open projects: Andors-Love, a turn-based RPG in C++ (2023); TrueJointTileMaker, a pixel-art and map editor for it (2024); PixRogue, a pixel-art Rogue in Python (2026).

  2. 11 Sep 2026

    The game

    The first commit of Galdhold (formerly VoxelRPG) — 234 files and 30,801 lines written before the repository existed.

    I started the game out of interest — the project grew beyond the plans.

    • Galdhold

  3. 25–29 Sep 2026

    The method

    The game repository gets rules for AI sessions (CLAUDE.md), and the next day a list of unfinished work (TODO.md).

    The game's architecture decision log (Р0–Р11) — the engine and the game share a repository, the engine stands on its own, and an automated check guards the boundary.

    The AI can forget the session; the project does not have to.

  4. 3–4 Oct 2026

    New systems

    DPlang starts — with a decision log, rules and checks from day one; Galdhold does not depend on it (Р18).

    The content system starts; the dpsmpx.com site generator follows the same day.

    Five more core repositories — DP-Verify, DPprofile, DPlearn, game market analysis and an undisclosed project. Four had a decision log on day one; DP-Verify started from a technical specification.

    • DPlang
    • SocialMediaImage
    • DP-Verify
    • DPprofile
    • DPlearn
    • game market analysis
    • 1 more project without a public name

  5. 5 Oct 2026

    An ecosystem

    From one game to an ecosystem of 9 repositories in 24 days.

    DPmeta — the first pass over the whole ecosystem — a map, contracts between repositories, risks.

    The dpsmpx.com domain is registered; the first regular site deployment.

    DPmetaApp, DPmonetization and DPvisualisation started on 5 October.

    • DPmeta
    • DPmetaApp
    • DPmonetization
    • DPvisualisation

  6. 6 Oct 2026

    Goal written down

    The ecosystem plan is written down: finished systems first, then one app over them.

    DP_AI_Orcestrator started on 6 October.

    • DP_AI_Orcestrator

  7. 10 Oct 2026

    All in one

    Ecosystem control: the author's single Android app, already with an AI subsystem for parallel sessions inside.

  8. 25 Oct 2026

    Four more projects

    Four more projects with work in October joined the system: AIM Trainer, DP_Clock, True Joint Tile Maker and Andors-Love.

    • DP AIM Trainer
    • DP_Clock
    • True Joint Tile Maker
    • Andors-Love

  9. 25 Oct 2026

    now

  10. phase A

    Finished systems

    Bring every project to a finished standalone system: tests, documentation, decisions, an integration contract.

    The projects stay standalone.

  11. phase B

    One app

    in progress since 11 Oct 2026

    Phase B has started: the app is built one function at a time, without waiting for every system to be finished.

    DPmetaApp — one mobile app over the finished systems: a shared model of state, events and knowledge.

The end goal

“First build solid standalone systems. Then make them understand each other correctly. Only after that, build a single application…”

— dpsmpx, the ecosystem plan, 6 Oct 2026
